# Windows 安装与验收

## 候选版本

Windows x64 安装候选可由源码构建，尚未创建正式 GitHub Release，也未完成干净 Windows 普通账号验收。不要把 CI 通过或本机自动测试当成已经对外稳定发行。

候选位于 `artifacts/desktop/release/0.1.1/TangerineReadingCompanion-0.1.1-win-x64-Setup.exe`，同目录提供 SHA256SUMS.txt。安装包未签名，Windows 可能提示未知发布者或阻止启动；记录具体提示，不要关闭安全软件或更改系统安全策略来完成验收。

## 安装和数据

1. 核对文件的 SHA-256 与同目录校验文件一致。可用系统 PowerShell 的 `Get-FileHash -LiteralPath '<安装包路径>' -Algorithm SHA256`。
2. 退出已运行的阅读伴侣安装版，双击 Setup。安装到当前用户，不请求管理员权限，不自动运行，不默认创建桌面快捷方式。
3. 从开始菜单打开“橘子阅读伴侣”。Windows“已安装的应用”应显示对应名称、版本和卸载入口。
4. 日常使用不需要 Node、npm、Git、Rust、开发服务器或终端。关闭窗口即退出，暂不提供托盘、全局快捷键和区域截图。

新装程序位于 `%LOCALAPPDATA%\Programs\Tangerine\TangerineReadingCompanion`。升级核对当前用户的旧登记、卸载命令和程序文件，在原产品目录更新。安装器拒绝不匹配的路径和目录联接，共享 Tangerine 父目录保留，不要手动把数据放进安装目录。书架和记录位于 `%APPDATA%/TangerineReadingCompanion` 下的应用存储，路径由系统解析，不硬编码用户名。

安装版与浏览器各自保存数据，不自动共享。若此前使用网页版或 VBS 快捷入口，先在原入口导出 JSON、确认文件保存，再在安装版“数据管理”中选择备份，查看预览、下载目标端备份并确认 merge-by-key 导入。备份未包含的本机记录保留，同 key 记录按导入内容覆盖；不要把来回导入当成双向同步。

升级和默认卸载保留用户数据，重装可重新读取。切换 Windows 账号不共享书架。应用不会读取日常浏览器数据库，也不会上传书架。原文、截图、OCR、模型内容与剧透授权不持久化；退出后需要重新输入会话 Key。

## 必要验收：只用临时测试书和测试备份

| 操作 | 预期 |
|---|---|
| 普通账号安装并从开始菜单打开 | 无管理员请求，无开发环境要求；出现书架，没有命令行窗口 |
| 不配置模型，添加一本文字信息的测试书，设置章节，记录名称和备注 | 保存反馈明确；退出重开后书籍、进度和备注保留 |
| 在当前段落输入一段临时文字，重开应用 | 原文为空；已确认记录仍在；没有恢复剧透授权 |
| 在“数据管理”导出 JSON | 弹出保存位置选择；确认文件确实存在，取消保存不会改动书架 |
| 导入另一份测试备份 | 显示新增/覆盖预览；要求先备份目标端并确认；原有无关书籍保留 |
| 打开《飘》、设置及地图面板，选择清晰截图并提取文字 | 面板和 OCR 能正常使用；本机 OCR 不要求模型 Key；地图在线服务按实际网络状态反馈 |
| 程序保持打开，再运行 Setup 或卸载 | 提示先退出并停止操作，原窗口和临时输入不被强杀 |
| 退出后覆盖安装同一候选 | 原书架可读取；这只是覆盖安装，不记为不同版本升级验证 |
| 退出后从 Windows 设置卸载，再重装 | 开始菜单和卸载登记正确移除/恢复；测试书和记录保留 |

使用应用一段时间后再迁入真实备份。不要为了测试删除真实书架、清空浏览器数据或选择真实私人文件。

## 可选体验

- 检查系统缩放、窄窗口、中文输入、键盘导航和剪贴板按钮。
- 在自己的服务商配置下测试模型与在线地图；不公开 Key，不把外部服务失败报告为本地记录失败。
- 若有干净 Windows 测试机，重复必要清单并记录 Windows 版本、普通账号、安装包 hash 与具体结果。开发机隔离 profile 不能代替这项验收。

## 自动验证证据

维护者运行桌面和安装回归，报告写到忽略的 `artifacts/desktop/smoke-result.json` 与 `installer-result.json`。每次重建以新的实际 hash 对应结果，不能沿用旧报告。安装器回归使用相同应用代码的低版本号 fixture，只证明安装器升级与数据保留，不证明历史格式迁移。构建和 CI 范围见 [桌面开发说明](native-development.md)。

正式公开分发前还需明确签名方案、完成目标系统验收，并提供与安装包对应的源码版本和许可证。没有获得发布授权时，不创建 Release。
