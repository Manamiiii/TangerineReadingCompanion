# 经典文学阅读伴侣：产品与技术规格

## 状态与定位

本文定义 Tangerine Reading Companion 的现有能力、内容建库方式、运行时边界、剧透安全规则和跨端技术边界。应用提供书架入口、个人书籍创建与删除、版本化资料读取、章节进度、Windows 剪贴板、设备端截图 OCR、本机已知名称扫描、可配置的窄范围模型候选识别、用户确认名称、按章节过滤、可全屏的真实地点互动地图、公网地图候选搜索、外部服务设置教程和确定性剧透门禁基础。正式《飘》章节实体与事实、历史地图图层、自由剧情问答、自动人物关系、Windows 全局快捷键和移动端原生分享入口仍属于待建设范围。

阅读伴侣面向“一次专注阅读一本书”的个人使用方式。使用者可以提前确定下一本书，因此系统以**按书预分析并构建版本化资料库**为主，运行时识别和大模型交互只承担辅助、消歧和补充解释，不追求在没有准备资料的情况下完整理解所有书籍。

核心目标是：

- 帮助读者理解地点、人物、时代背景和已读内容之间的关系。
- 地图类纯空间信息可以直接、宽松地展示。
- 任何存在合理剧透概率的回答或展示都必须在内容出现前给出强提醒。
- 读者明确授权后才生成或展示潜在剧透内容。
- 工具不注入、不逆向微信读书，也不依赖其私有接口。

## 使用范围

### 界面层级

进入「经典文学阅读」场景后先显示书架，不自动打开目录中的第一本书。选择书籍后进入该版本独立的阅读空间，书内只选择阅读章节；通过“返回书架”切换书籍。这样可以在增加新书时保持每本书的版本信息、进度和读者确认记录相互隔离。

书架中的“添加书籍”可以只凭书名、作者、版本信息和章节数或逐行目录建立个人资料包，并可选择内置配色文字封面或上传不超过 1.5 MB 的 PNG、JPEG、WebP 封面。书架卡片只突出封面、书名、版本和阅读入口；“内置”或“个人书籍”使用卡片角落的小型标记，内部准备数量不作为读者选书信息展示。用户也可以选择书籍详情或版权信息截图：设备端 OCR 先提取文字、保留字段行边界并反复清理中文误空格；关键字段缺失或标签异常时，只加载简体中文语言数据的整页书目模式执行第二次 OCR，减少中文姓名被误判成拉丁字母的情况，系统选择结构更完整的结果。确定性解析器优先读取 `字段名：字段值` 形式的书名、作者、译者、出版社等字段；OCR 把多行合并时，解析器使用后续字段标签作为当前值的结束边界。作者前与出版社前的未知短标签行可以按版权页字段顺序恢复为低置信书名和译者。模型配置完整时，同一次用户操作会把 OCR 原文、本机候选和低置信字段发送给模型；模型可以使用公开书目知识，以准确 ISBN、出版社和出版日期为主要证据校对书名、作者与译者。合并结果保留本机从明确标签读取的可靠书名和译者，低置信字段允许由模型纠正；最终作者或译者发生变化时，界面标记“模型校对”。识别完成后，界面显示识别器版本、最终书名、作者和译者，并允许按需展开本机 OCR 文字，用于确认当前页面资源版本和定位识别差异。识别结果只填充表单，用户核对后才创建书籍，截图与 OCR 文字不持久化。封面随个人资料包保存在 Dexie `meta` 表，不修改 schema。

个人书籍默认勾选“创建后用 AI 准备基础资料”。模型只生成最多 50 个无剧透人物、地点、概念和事件名称及常见别名，不生成关系、剧情、章节、解释或坐标；结果自动合并为个人资料包的隐藏 `onDemandEntities`，无需尚未阅读本书的用户逐条审核。只有名称以后在读者当前输入中精确出现时，本机扫描才显示它，读者再按正常阅读动作记录到当前章。重复运行只补充新名称，不清空阅读记录；模型失败不影响书籍创建。该个人词典属于用户主动生成的辅助资料，不是正式来源、版本证据或客观首次出现章节。个人书籍可以删除；版本化内置书籍在书架中明确标记为“不可删除”，其正式资料仍必须经过 staging → preview → 显式发布流程。

模型提示词采用版本化契约。个人书籍运行时初始化与内置书正式预制使用不同提示词和输出权限：前者只允许自动保存隐藏名称词典，后者只允许生成带来源和阻塞项的 staging 候选。提示词标识、标准输入输出和维护规则见 [`model-prompts.md`](model-prompts.md)。

书架同时展示首次试用路径和当前能力边界。Windows 首版支持安装为 PWA 独立窗口、剪贴板输入、截图 OCR 和可选模型候选识别；自由剧情问答、自动人物关系和移动端原生分享保持关闭。具体试用步骤见 [`trial-guide.md`](trial-guide.md)。

选书后的主空间固定使用“阅读输入 / 已遇到 / 地图 / 设置”四个任务 Tab，当前进度存在已解锁无剧透背景或正式事实时增加“背景资料”，并显示当前可查看数量。章节选择位于书籍信息区右上角；阅读输入顶部并排提供剪贴板与截图两种来源，文字进入同一个当前段落框。所选截图默认只显示缩略图、文件名与提取操作，点击缩略图后才使用遮罩层展示适应窗口的大图。段落下方在桌面端使用等高、等宽的“无剧透问答”和“记录阅读线索”任务区：本机匹配与模型发现集中在记录区。选中段落文字后使用无重复字段标题的名称类型、地点性质和确认操作快速写入；没有原文选区的手工补记统一放在“已遇到”，避免阅读页出现重复录入入口。模型候选允许在保存前修改原文名称、人物/地点/概念/事件类型和地点性质；模型同时接收最多 60 条已有资料名称的受限索引，可靠识别出译名、简称、全名或原文名属于同一对象时返回索引内稳定 id。界面标明配对的标准资料名，索引外 id 被丢弃；读者编辑名称或类型会解除配对。确认后保留段落实际名称并保存资料实体 id，不同译名因此共享背景、地图和出现章节，不会成为重复对象。地点无法由当前段落确认时默认保持“不确定”，不会因默认值发起公网搜索。候选行使用稳定的字段列和操作列宽度，置信度与资料配对紧跟名称字段标题而不另占一行，写入后保留并显示当前章已记录状态；段落发生变化时旧候选保留原有高度但进入不可记录的过期状态，重新识别后整体替换，动态结果区不参与浏览器滚动锚定。“已遇到”按人物、地点、概念和事件分组，提供类型筛选、每页 10/20/50 条、首页、末页和指定页跳转。列表使用自适应多列紧凑卡片，只显示名称、首次与最近章节、出现次数和少量状态；“查看详情”打开独立阅读记忆弹层，集中处理出现章节、当前章补记、500 字个人备注、地点性质、资料匹配和地图位置，不在列表内展开或改变页面高度。地点性质说明使用折叠帮助：不确定地点不开放搜索，现实地点可确认现代位置，虚构地点只使用宽泛参考区域，有现实原型时明确区分原型和作品地点，位置模糊时只确认到国家、州、省或地区。“背景资料”把当前章节已解锁的 `safeNote` 汇总成等宽卡片，正文优先显示，来源链接默认折叠；正式事实使用独立分区并继续经过风险门禁。地图详情固定分为现代位置和无剧透背景，来源同样折叠；距离工具要求读者选择起点、终点并点击计算，每次只产生一对地点的方向和球面直线距离。地图使用独立整栏画布；模型和地图服务的配置、清除、数据边界与教程统一位于“设置”。设置页显示应用版本、部署提交短标识和当前资料包版本，并可导出当前书的试用反馈包。反馈包包含版本、进度、阅读记忆、资料配对、地图确认，以及当前浏览器会话内最近 30 次关键 OCR、模型、地图和建书操作的脱敏结果；诊断只使用固定功能名、供应商类型、成功/失败和错误类别，不保存错误原文。反馈包不包含 API Key、原文、搜索词、截图、模型内容或完整 User-Agent。业务页面不重复展示“已配置”“点击才会发送”“仅保存在本机”等静态说明，只保留缺少配置、处理进度、处理结果和坐标精度等会影响当前操作的信息。Tab 只改变当前任务视图，不改变章节门禁、资料状态或本机持久化语义。

### 目标终端

- Windows 是当前实现目标：使用 Edge 或 Chrome 访问后可安装为 PWA 独立窗口，从微信读书复制文字或选择截图。
- iPhone 和华为平板属于后续适配目标；当前网页仍可打开，但不承诺原生分享、安装和 OCR 体验。

### 内容入口

微信读书没有可依赖的第三方阅读器插件接口，因此阅读伴侣作为独立工具接收用户主动提供的内容：

1. 优先接收微信读书选中文字后的复制或系统分享。
2. 无法分享文字时，接收当前页或当前段落截图并在设备端 OCR。
3. Windows 支持浏览器剪贴板按钮、`Ctrl+V` 和截图文件选择；全局快捷键及直接区域截屏仍需要原生壳。
4. iOS 通过 Share Extension 接收文字、图片或链接。
5. 华为 Android 设备通过 Android Share Target 接收内容；纯 HarmonyOS 通过 ArkTS 分享接收能力适配。

系统不能拦截微信读书原生页面里的地名点击。接近原始设想的交互是：用户分享或截取当前页后，工具在识别结果上框出地名，用户点击识别出的地名查看地图。

## 按书提前建库

### 当前书籍版本

运行时目录包含《飘》的指定中文版本：

- 作品：玛格丽特·米切尔《飘》（Gone with the Wind）。
- 译者：范纯海、夏旻。
- 出版社：长江文艺出版社。
- 出版时间：2018 年 5 月。
- ISBN：`9787570202188`。
- 数字阅读入口：微信读书。
- 章节边界：连续 1–63 章，稳定 id 为 `chapter-01` 至 `chapter-63`。

版本信息来源于使用者提供的微信读书详情和版权信息。纸质上下册分界不作为数字阅读进度边界。资料包的实体、事实、来源和地图字段必须经过后续审计才可加入正式集合。

### 建库输入

准备下一本书时创建一个独立书籍资料包，至少记录：

- 书名、作者、原作语言和作品标识。
- 阅读版本、译者、出版社或电子版特征。
- 章节目录及章节稳定标识。
- 故事时间范围和主要地理范围。
- 可合法使用的参考文本、公开资料和地图资料来源。

不同译本可能使用不同的人名、地名和章节划分，资料包必须区分版本；无法确定版本时应降低章节定位置信度并采用更保守的剧透策略。

### 预分析产物

大模型可以在建库阶段生成候选内容，但候选必须结构化、可追溯并允许人工修正。资料包包含：

- 地点实体、别名、原文名、译名和地理层级。
- 真实地点坐标、历史名称和适用时间范围。
- 虚构地点、原型地点或模糊区域及其置信度，禁止伪造精确坐标。
- 地点首次出现章节和各章节已经揭示的地点事实。
- 人物、别名、称呼及按阅读进度逐步揭示的关系。
- 历史事件、时代概念及其与作品剧情的隔离标记。
- 已审计的地图图层、路线和时间线片段。
- 每条事实的来源、风险级别、最早可揭示进度和风险类别。

建议的数据单元包含：

```json
{
  "id": "place-stable-id",
  "name": "地点名称",
  "kind": "place",
  "placeKind": "real | fictional | prototype | approximate",
  "aliases": [],
  "parentLabel": "地理层级说明",
  "revealAt": {
    "chapterId": "chapter-12"
  },
  "sourceIds": ["source-stable-id"],
  "geometry": {
    "type": "point | area",
    "latitude": 0,
    "longitude": 0,
    "radiusKm": 20
  }
}
```

每个正式实体必须引用已批准来源和指定版本中的首次可揭示章节。真实地点或有来源支持的原型地点可以使用 `point`；模糊区域使用带半径的 `area`；虚构地点不得通过 `point` 伪造精确坐标。无章节证据或无批准来源的候选不进入正式资料包。

事实数据单元包含：

```json
{
  "id": "fact-stable-id",
  "bookId": "gone-with-the-wind",
  "editionId": "edition-stable-id",
  "entityIds": ["place-atlanta"],
  "kind": "spatial | character | plot | history | concept",
  "content": "结构化事实或展示数据",
  "revealAt": {
    "chapterId": "chapter-12",
    "anchor": null
  },
  "riskLevel": "safe | potential | high",
  "riskCategories": ["location_significance"],
  "sourceIds": ["source-stable-id"],
  "confidence": 0.96
}
```

每条正式事实必须包含类型、内容、实体引用数组、已批准来源、指定版本中的可揭示章节、风险级别和风险类别。风险类别只能使用系统预定义枚举，警告界面不读取模型生成的自由文本。`revealAt` 是可展示边界，不代表内容一定应自动展示；`potential` 和 `high` 仍需经过剧透门禁。

### 建库流程

```text
输入书目与版本
  → 收集合法参考资料
  → 划分章节与稳定阅读进度
  → 大模型批量提取实体和候选事实
  → 地名数据库校验坐标和别名
  → 标注 revealAt、风险等级和来源
  → 人工抽查高风险事实与虚构地点
  → 生成版本化资料包
  → 预览报告确认后发布
```

资料包采用版本化的 staging → preview → 显式发布流程。运行时只读取已发布资料，不直接把未经检查的大模型批量结果当作正式内容。

当前发布目录与命令为：

- `scripts/reading-companion/data/staging/`：版本化研究输入、来源状态、实体和事实候选。
- `scripts/reading-companion/data/preview/`：由 staging 生成的逐书完整发布候选、统一 catalog 和审计元数据。
- `npm run preview:data`：生成 preview。
- `npm run check:preset`：比较 preview 与正式资料并在 `artifacts/reading-companion/` 生成报告。
- `READING_PACKAGE_OVERWRITE=CONFIRM_READING_PACKAGE npm run apply:preset`：显式写入正式资料包。
- `npm run check:packages`：校验运行时目录和正式资料包。
- `npm run audit:quality`：生成背景覆盖、地点几何、来源 URL、中文候选名称和阻塞项报告。
- `npm run audit:links`：在质量报告中增加外部来源在线可用性探测。

资料源状态使用 `approved`、`candidate` 和 `rejected`。只有 `approved` 来源可以进入运行时资料包；候选和拒绝项只保留在 staging 与 preview 审计元数据中。来源不限制语言：中文出版社、图书馆、大学、博物馆、政府机构和可靠学术页面可以与外文资料一起使用。中文来源必须直接支持对应书目、译名或背景说明；转述性中文页面不能替代更接近事实源头的官方或一手资料，也不能替代指定中文译本的章节边界证据。

实体与事实研究结果分别保存在 `entityCandidates` 和 `factCandidates`。每项都包含候选状态、结构化数据、引用来源、阻塞项和审阅备注。`candidate` 必须至少声明一个阻塞项；候选数组不会被发布管线隐式合并到正式 `entities` 或 `facts`，只有人工核对来源、指定译本别名和 `revealAt` 后，才可显式移入正式集合。preview 和检查报告会列出候选 id 与阻塞项，但运行时资料包不包含候选内容。

“待审核”是资料包维护状态，不是交给普通读者的任务。维护者负责逐项打开来源，确认来源直接支持名称、背景说明或几何信息，检查中文名是否属于指定译本，判断内容是否涉及剧情，并为需要按进度展示的资料核对 `revealAt`。公开权威来源足以支持、且脱离作品剧情仍成立的历史或地理背景，可以由维护者审核后进入隐藏按需资料；人物关系、剧情事实和客观首次出现章节缺少指定译本证据时继续保留候选。尚未读过本书的使用者不需要判断这些内容，也不需要为了通过审核提供整本原文；实际阅读时提交的当前段落只作为最小版本证据，不保存原文全文。

管线枚举 staging 目录内的全部 JSON，不保存单一书籍硬编码。每份 staging 都声明唯一 `slug`、顺序、catalog 展示信息、版本、来源状态、实体和事实：

- 首次发布的新书必须提供完整 `package`，包括作品、版本和稳定章节。
- 已有书更新可以提供 `basePackagePath`，在正式包的作品、版本和章节基础上替换受审计的来源、实体和事实。
- preview 自动生成 `presets/reading-companion/{slug}.json` 目标和统一 catalog 条目。
- slug、顺序、资料包 id 和 catalog 路径必须唯一且满足固定路径格式。

因此，新书接入的数据准备不要求修改浏览器组件或发布脚本；建库质量仍通过首本真实书籍的完整流程逐步校准。

### 当前资料源候选

- 使用者提供的微信读书版本、版权信息和详情页简介是已批准来源，用于版本、译者、ISBN、1–63 章结构，以及简介中明确出现的斯佳丽、瑞德、艾希礼、梅兰妮四个短名；它不包含正文，不能用于首次出现章节。
- [Library of Congress · America Reads](https://www.loc.gov/exhibits/america-reads/1900-to-1949.html#obj019) 用于候选原作书目和作品历史范围，不用于中文译文章节定位。
- [U.S. Census Bureau · Gazetteer Files](https://www.census.gov/geographies/reference-files/time-series/geo/gazetteer-files.2025.html) 是已批准的美国政府地理数据来源，用于现代行政区、GEOID 和代表坐标；代表坐标不是边界，也不能证明作品年代的边界或交通状况。
- [U.S. Census Bureau · Regions and Divisions](https://www.census.gov/programs-surveys/economic-census/guidance-geographies/levels.html) 支持把 South Region 作为一种现代统计口径，并明确其三个下级分区；系统用它解释一种可核验的范围定义，但不把统计口径冒充所有历史语境中的“美国南方”。[New Georgia Encyclopedia · Georgia Quick Facts](https://www.georgiaencyclopedia.org/quick-facts/) 支持佐治亚的建州年份和州府沿革。
- [U.S. Census Bureau · Georgia Incorporated Places](https://tigerweb.geo.census.gov/tigerwebmain/Files/acs25/tigerweb_acs25_incplace_ga.html) 用于核对亚特兰大和琼斯伯勒的现代代表坐标。
- [Atlanta History Center](https://www.atlantahistorycenter.com/blog/so-red-the-rose-the-gone-with-the-wind-that-never-was/) 用于区分真实的亚特兰大地点与虚构种植园，并防止给塔拉等虚构地点伪造精确坐标。
- [New Georgia Encyclopedia · Gone With the Wind](https://www.georgiaencyclopedia.org/articles/arts-culture/gone-with-the-wind-novel/) 与 [Clayton County](https://www.georgiaencyclopedia.org/articles/counties-cities-neighborhoods/clayton-county/) 用于候选时代范围、地点名称和地区背景。包含剧情概述的页面仅供建库审阅，不能直接成为运行时安全内容。
- [National Park Service · The Plantation System](https://www.nps.gov/articles/plantationsystem.htm)、[Library of Congress · Abraham Lincoln](https://www.loc.gov/exhibits/civil-war-in-america/biographies/abraham-lincoln.html) 和 [National Park Service · The Civil War](https://www.nps.gov/civilwar/index.htm) 是已批准的独立历史来源，分别支持“种植园”“林肯”和“南北战争”的简短无剧透背景注释；它们不用于推断作品中的关系、行动、意义、结局或首次出现章节。
- [University of Virginia](https://www.virginia.edu/about-uva/)、[The University of Alabama](https://www.ua.edu/about/history/) 和 [University of South Carolina](https://www.sc.edu/about/our_history/university_history/timeline/index.php) 的官方页面支持三所学校的创建年份、历史名称和现代所在地；[Digital Library of Georgia · Fayetteville Academy](https://dlg.usg.edu/record/nge_ngen_m-9272) 支持现实学校与虚构学校原型的区分。学校注释不用于推断作品人物经历或章节位置。
- [Atlanta History Center · Turning Point](https://www.atlantahistorycenter.com/exhibitions/turning-point-the-american-civil-war/) 支持亚特兰大在美国内战时期作为交通、工业和军需储运中心的独立背景；New Georgia Encyclopedia 的 Clayton County 条目支持克莱顿县和琼斯伯勒的行政与名称沿革。这些内容不用于解释作品中发生了什么。
- [Library of Congress · General Maps](https://www.loc.gov/collections/general-maps/about-this-collection/rights-and-access/) 用于候选历史地图。每个地图条目必须单独检查 Rights Advisory 与署名要求。
- 互动地图支持两种可切换底图：国际模式使用 [OpenStreetMap](https://www.openstreetmap.org/copyright) 在线标准瓦片，免 Key，但在国内网络可能需要 VPN；国内模式使用[天地图](https://www.tianditu.gov.cn/)矢量底图与注记，需要使用者在设置中填写浏览器端 Key。选择和 Key 只保存在当前浏览器的 `localStorage`，不进入资料包、IndexedDB 导出或仓库。设置页提供天地图控制台入口、浏览器端应用申请步骤、清除 Key 和回到地图验证的说明。两种模式都始终显示供应商署名，不提供瓦片预取或离线下载。瓦片只在拖动结束后更新，不在缩放动画的中间级别加载，使用一个瓦片宽度的视野缓冲；一本书首次打开地图后会在其他书内 Tab 间保留地图实例，避免来回切换重复初始化。地图显示当前实例加载的底图和注记瓦片数；该值用于本机估算，浏览器缓存会使服务商实际计量少于本机加载数。切换书籍或地图供应商时重新计数。底图配置集中在 `src/features/reading-companion/map/mapConfig.js`，底图只负责显示，不能成为正式地点坐标或虚构地点定位的证据。
- 资料包外地点可以由读者主动发起公网地图搜索。国际模式使用 Nominatim，国内模式使用天地图地名搜索并复用浏览器端 Key。两种服务都限制为点击后搜索、同一供应商每秒最多一次实际请求、最多五条结果，并缓存会话内重复查询。界面会在请求前说明搜索词将发送给所选服务，不提供自动完成或后台批量查询。
- 公网搜索结果只是现代地图候选。新记录的地点默认为“不确定”，不提供搜索。现实地点可以使用作品名称或读者编辑的现代地图词搜索精确候选；虚构、原型和模糊地点不能发送作品名称，只能由读者另行填写现实国家、州、省或地区并设置宽泛参考半径。系统不猜测历史名称、旧译名与现代地名的对应关系。读者确认结果后，系统把点坐标、服务返回的 GeoJSON 点/线/面或参考区域作为 `observedEntities[].mapLocation` 保存到个人阅读状态。河流、山脉和行政区在地图服务提供几何时按路径或范围展示；缺少几何时只显示代表点。该位置随章节边界显示，标记为个人确认内容，不写回正式资料包；宽泛参考区域不参与精确距离计算。

这些外部来源均不能替代指定中文译本对 `revealAt` 的章节证据。缺少对应章节文本时，实体和事实保持待审，不进入正式资料包。

没有可用原文时，章节仍有两项确定用途：

- `currentChapterId` 表示读者实际进度，负责隐藏较后章节的本地记录并为未来检索限定上界。
- `observedEntities[].firstSeenChapterId` 表示读者主动确认“最晚已在这一章遇到该名称”；`encounterChapterIds` 保存读者明确记录过该名称的章节集合，旧记录没有该数组时以 `firstSeenChapterId` 作为唯一一次记录。`note` 是最多 500 字的个人备注。三者都是个人阅读记忆，不宣称作品中的客观出现次数或首次出现章节，也不会自动批准候选实体、坐标、人物关系或剧情事实。

正式资料包的 `revealAt` 与本地 `firstSeenChapterId` 不可互相替代。前者需要指定版本证据并可供所有使用者复用；后者只来自当前读者输入，保存在当前设备，可在没有全文、OCR 和模型时工作。读者退回较早章节时，系统隐藏锚定在较后章节的名称，避免本地记录本身造成剧透。

资料包可以另带 `onDemandEntities`，用于无原文条件下的按需精确匹配。该集合遵守以下安全边界：

- 不在界面中列出候选、提供自动完成或做模糊搜索。
- 只有用户已经输入同名且同类型的名称后才返回结果；匹配对全角/半角、首尾空格和英文大小写做规范化，但不允许前缀或近似匹配。
- 只包含已批准来源支持的名称、真实/虚构分类、地理层级、现代代表坐标和范围说明。可选 `safeNote` 必须由独立批准来源支持、限制在 400 字符内，并且只说明不依赖作品情节的概念或历史背景；`safeNoteSourceIds` 必须逐项引用 `sourceIds` 中直接支持该注释的来源。不得描述人物关系、作品中的行动、地点剧情意义、命运、结果或后续影响。
- 解锁章节取自本地 `firstSeenChapterId`，界面明确标记为“读者确认后精确解锁”，不把它冒充指定译本的客观首次出现章节。
- 真实地点坐标可以进入互动地图；虚构地点不伪造精确坐标。`safeNote` 与其他按需字段一样，只在读者输入精确匹配并确认该名称后显示；注释下方只列出 `safeNoteSourceIds` 指定且具有 HTTP(S) 地址的来源链接。退回较早章节时，按需实体、名称、注释和来源一起隐藏。

当前《飘》资料包包含 40 个按需精确匹配实体，包括 21 个人物、12 个地点、5 个概念和 2 个事件。作品人物只提供名称、原文名和经审计的别名；现实地点使用明确标注的现代代表位置；虚构地点不提供伪造精确坐标，原型或模糊地点只使用有来源的参考区域。部分现实地点、概念和历史事件在精确解锁后另有批准来源支持的简短离线背景注释，但不附加作品人物关系、情节解释或历史评价。所有名称与注释都不会在读者输入前列出，也不包含人物关系或剧情事实；具体数量以发布目录的 `preparedSummary` 为准。

不得绕过微信读书鉴权、反自动化措施或私有接口批量获取作品全文。原文和参考资料的获取、保存与模型传输必须符合其授权范围；运行时只处理用户主动提供的最小必要段落。模型可能凭训练形成对知名作品的概括性知识，但训练语料清单、具体版本、译名和章节证据不可由运行时验证，因此模型内部知识只能生成研究候选，不能单独成为正式资料的来源、版本边界或剧透边界。

### 能力归属

- **系统能力**：仓库中的确定性代码、资料包 schema、校验器、章节过滤、空间投影、剧透规则、发布命令和测试。它们可在没有当前开发会话和模型的情况下重复运行。
- **建库候选**：开发时由 Codex、其他模型或人工研究形成的实体、事实和来源建议。它们必须保存在 staging，并在来源与章节边界获批后才能成为系统正式数据。
- **运行时模型能力**：应用提供 OpenAI Chat Completions 兼容适配器，并为智谱、DeepSeek、MiniMax、OpenAI 和自定义接口提供可编辑预设。用户可以在供应商间切换，每家接口地址和模型名分别保存在 `localStorage`，每家 API Key 分别存在当前 `sessionStorage`。模型可以从当前小段识别名称候选，并在受限资料索引中推荐同一实体的稳定 id；也可以从书籍详情 OCR 文字整理书目字段，并结合书名和章节语境提供最多三个国际地图检索词。模型不能写入正式资料包、生成事实或绕过章节门禁，名称配对也必须由读者确认后才进入已遇到记录。成功结果使用最多 30 条的页面内临时缓存，相同接口、模型、输入、语境与资料索引不重复请求；刷新页面后缓存清空。具体配置见 [`模型供应商配置`](../model-provider-setup.md)。

测试夹具只证明系统可以处理某种数据结构，不代表对应书籍、地点或事实已经进入正式资料库。

## 运行时能力

### 无模型也可工作的能力

- 从 Windows 剪贴板读取当前小段，或使用 Tesseract.js 在设备端对中英文截图执行 OCR；OCR 语言数据随应用发布，识别结果会合并截图硬换行、移除中文字符之间的误空格并保留英文单词空格，随后只进入当前页面并需人工核对。识别计算使用浏览器 Web Worker 与 WebAssembly，因此可在 Windows 和 macOS 的现代浏览器运行；Tesseract worker/core 首次初始化仍可能访问其 CDN。
- 根据正式资料包和当前章节确定性过滤可见实体。
- 在 Leaflet 互动地图中展示已审计地点，支持拖动、缩放、触控、列表与标记联动和多地点视野适配；OpenStreetMap 在线瓦片不可用时，地点标记、坐标和详情仍可降级展示。
- 读者选择两个具有可靠代表坐标的已读地点并点击计算后，给出这一对地点的方向和球面直线距离；不预先展开全部组合，也不推断路线、交通方式或剧情移动。
- 标记真实地点、虚构地点、原型地点和模糊区域。
- 查询书籍资料包内的别名、译名和已审计说明。
- 按当前阅读进度过滤人物、地点、关系和时间线。
- 保存当前书籍、版本、章节和已查看实体。
- 记录读者在当前章节主动确认遇到的人物、地点、概念或事件名称；同名同类型记录去重，并保留更早的确认章节。
- 将读者已确认名称与资料包中的窄范围公开候选做精确匹配，并在匹配后显示经过来源审计的安全分类与空间字段。
- 用户粘贴或 OCR 得到当前段落后，系统在输入停止约 250 毫秒时自动扫描文本中实际出现的 `onDemandEntities` 名称、别名和读者已经记录的名称；英文匹配要求完整词边界。本机扫描不使用中文分词、称谓、说话动作或地点后缀猜测陌生实体，避免把“他们刚被佐治亚大学”之类的句段整体误记为地点。陌生名称由读者显式运行模型识别，或直接选中段落文字并按人物、地点、概念或事件记录。所有结果都需用户确认才写入已读记忆。
- 同名同类型记录已经存在于较后章节时，扫描结果显示“提前到当前章”，确认后修正 `firstSeenChapterId`；记录已经位于当前章或更早章节时显示原章节并禁用重复添加。
- 对资料包未收录但读者已经记录的地点发起显式公网地图搜索，并在读者选择某个现实地点候选后保存个人地图位置；国际搜索请求中文优先结果和多语言名称，结果存在中文名时同时展示中文名。已配置模型时，读者可以显式让模型结合地点原名、书名和当前章节生成最多三个按精确到宽泛排序的地图检索词，再选择、编辑并搜索；最后一个候选用于提供可能的城市、州或地区。历史机构没有独立现代地图对象且精确搜索为空时，读者可以显式切换到“参考区域兜底”：系统使用最宽泛候选或读者填写的现实地区继续搜索，确认后保存带半径圆圈的 `fallback-area`，不会伪装成历史机构的精确坐标，也不参与精确距离计算。虚构、原型和模糊地点可以由读者另行输入现实地区名并确认宽泛参考区域。搜索服务不会判断作品里的地点身份，未经确认的结果不会进入地图。

### 运行时大模型的辅助职责

- 从当前段落或 OCR 结果中识别原样出现的人物、地点、概念和事件名称。
- 把当前段落名称与已有资料的标准名、原文名和别名做受限配对；只能返回输入索引中的稳定 id，应用负责校验并等待读者确认。
- 从书籍详情截图的 OCR 文字中整理有限书目字段，且不凭模型常识补全截图未提供的信息。
- 为个人书籍自动准备无剧透隐藏名称词典；用户无需在阅读前逐条判断，名称只有在当前原文精确命中后才出现。
- 回答概念、时代背景、语言含义和当前段落问题；只发送当前问题、当前段落、书名和章节标签，回答临时显示且不写入资料库。包含“后来、下一章、最终、结局、身份秘密”等明显后续导向的问题在请求前由本机拒绝；回答出现章节号、结局、身份真相或后续命运信号时停止显示。
- 结合地点原名、当前书名和章节标签提供国际地图检索词候选，不直接确认地图位置。
- 模型不能直接确认现实地点、生成正式关系或事实；地点无法由当前段落确定时必须保持“不确定”。
- 自由剧情问答、后续人物关系和事实生成属于后续能力，并继续受双阶段剧透门禁约束。

运行时大模型不是坐标、阅读进度或剧透授权的最终决定者。确定性代码负责：

- 当前阅读边界。
- 允许检索的资料范围。
- 地图坐标和距离。
- 风险级别触发条件。
- 是否显示确认界面。
- 用户是否授权查看潜在剧透。

### 已读记忆

即使书籍已经预建库，系统仍保存一份本地已读状态：

- 当前书籍和版本。
- 已确认章节及可选的段落锚点。
- 已经在阅读内容中出现的实体。
- 用户主动输入的名称、明确记录过的章节集合和个人备注；该记录不附带未经审计的外部事实。
- 用户主动确认或纠正过的地名映射。
- 用户对剧透内容的单次授权，不默认转化为全局授权。

资料包定义“经过版本证据审核后，作品资料何时可以揭示”；已读记忆定义“当前读者实际读到哪里，以及主动确认遇到了什么”。正式资料按两者交集过滤，本地名称按其用户确认章节过滤。

## 地图与理解辅助

### 地图

- Leaflet 负责浏览器内的拖动、缩放、触控、标记与视野控制。
- OpenStreetMap 或天地图瓦片提供在线现代地理背景并显示供应商署名；瓦片服务没有离线或可用性保证。
- 当前进度没有可定位地点时仍显示宽泛背景底图和明确说明，但不列出按需地点名称；该默认视野只帮助建立大致地理感，不代表作品地点或故事空间。
- 地图使用独立任务 Tab、整栏大画布和全屏按钮。优先请求浏览器原生全屏；原生能力不可用或被拒绝时使用覆盖当前窗口的全屏回退，`ResizeObserver` 保证 Leaflet 在尺寸切换后重新铺满容器。
- 真实地点使用已批准坐标显示点标记，模糊区域使用带半径的范围，地点列表与地图选择联动。
- 读者从公网地图搜索结果中确认的现实地点使用独立标签显示，只属于个人已读记忆，不等同于已批准坐标。
- 多个已读地点之间展示方向和球面直线距离，不把它解释为历史道路距离或人物行程。
- 虚构地点没有可靠几何信息时只显示地点卡片，不伪造现实地图坐标。

故事年代适用的名称、边界、交通方式、历史地图覆盖层和已读路线仍需独立来源及版本边界审核。

地图面板把纯空间信息和剧情解释分开。坐标、距离等安全字段可以立即出现；“为什么重要”“谁将在这里做什么”等内容进入剧透门禁。

### 人物与时代背景

- 当前进度内的人物别名、称呼和已经明确的关系。
- 人物上一次在已读范围内出现的地点。
- 时代制度、社会概念和历史背景。
- 作品事实与现实历史使用不同标签。

现实历史也可能暗示剧情。只要历史说明与作品人物、地点后续命运建立联系，就按潜在剧透处理。

## 剧透安全契约

### 基本原则

- 地图类纯空间事实使用明确白名单，可以直接展示。
- 只要存在合理概率涉及剧透，就必须先警告，后生成或展示。
- 无法确定风险时按潜在剧透处理。
- 警告本身不得包含具体剧情事实。
- 用户即使主动询问结局或后续剧情，仍需经过强提醒。
- 不使用“先生成、再模糊遮挡”的方式保护内容。

### 风险分级

#### `safe`

默认允许直接展示：

- 经纬度、方向、距离和行政层级。
- 不涉及后续命运的真实或虚构地点类型。
- 故事时间点之前已经成立的纯地理事实。
- 与剧情意义隔离的地图底图和历史边界。

安全白名单只适用于具体字段，不自动覆盖整个地图弹窗。

#### `potential`

展示前必须强提醒：

- 地点在作品中的重要性。
- 人物为什么前往或离开某地。
- 人物关系、动机和立场解释。
- 可能超过当前进度的历史与剧情联系。
- 路线、时间线或关系图中尚未确认安全的节点和边。
- 模型生成且不能证明完全来自已读范围的内容。
- 当前章节、版本或事实揭示边界不明确的内容。

#### `high`

展示前必须二次确认：

- 结局。
- 人物死亡、婚姻结果或最终命运。
- 身份反转和核心秘密。
- 明确发生在当前进度之后的关键剧情。

### 强提醒交互

潜在剧透警告只显示无细节的风险类别：

```text
⚠️ 以下内容可能涉及剧透

可能涉及：人物关系、地点的后续意义或当前进度之后的事件。
当前阅读进度：第 12 章。

[保持隐藏] [仍然查看]
```

- “保持隐藏”是没有运行时模型时的默认操作，且不会把事实内容写入页面。
- “仍然查看”使用明显警示样式。
- `high` 内容在“仍然查看”后增加第二次确认。
- 授权默认只对当前一次内容有效。
- 警告原因只使用预定义类别，不让模型写可能泄露剧情的自由文本。
- 接入运行时模型后可以增加“只生成严格无剧透版”，但生成结果仍需经过展示前扫描。

### 双阶段门禁

```text
用户请求或即将展示的组件
  → 检查当前版本和阅读进度
  → 只检索进度内资料
  → 前置风险分类
      ├─ safe：允许生成
      └─ potential/high：停止并先提示
  → 用户选择严格版或授权版
  → 生成候选内容
  → 展示前二次扫描
      ├─ 通过：展示
      └─ 风险升级：丢弃候选并重新提示
```

流式输出只能在前置门禁通过后开始。生成后的候选在二次扫描通过前不得写入可见 DOM、通知、无障碍文本或预览摘要。

### 覆盖范围

剧透门禁覆盖所有可能呈现内容的入口：

- 聊天回答。
- 地图标记、弹窗和路线。
- 人物关系图的节点与连线。
- 时间线。
- 搜索建议和“你可能还想问”。
- 图片标题、来源标题和摘要。
- 已读总结和通知。

## 应用结构

运行时代码集中在 `src/features/reading-companion/`；书架、建书和安装入口由 `ReadingLibrary` 承担，书内任务编排由 `ReaderTool` 承担，地图、领域规则、模型契约和持久化按子目录隔离。维护脚本、版本化研究数据和专用测试集中在 `scripts/reading-companion/`。应用入口只承担独立外壳、阅读专用备份和恢复；专用样式在 `src/styles.css` 中使用 `reader-` 前缀。

### 数据边界

当前 Dexie schema 保持 v1，只包含 `meta`。若专用阅读进度表、缓存表或授权记录确实需要新索引，必须另行设计并得到用户明确授权。

书籍正式资料包适合存放为版本化静态 JSON；读者进度、实体纠正和单次偏好保存在 IndexedDB。用户数据不得被预置更新覆盖。

### 大模型服务边界

应用是纯静态站点，模型供应商密钥不能写入仓库或公开构建产物。长期服务形态从以下方式中明确选择：

1. 个人 BYOK：密钥只保存在用户设备本地，简单但跨设备和密钥保护能力有限。
2. 独立的轻量服务或 Serverless 代理：密钥留在服务端，适合正式跨端使用，但会引入后端、鉴权和隐私策略。
3. Windows 本地模型：隐私较好，但不能自然覆盖 iPhone 和华为平板。

模型访问通过独立适配接口提供，主界面和资料包不绑定具体供应商：

```text
analyzeExcerpt
resolveEntities
classifySpoilerRisk
generateExplanation
scanGeneratedContent
```

### 跨端外壳

```text
共享 React/PWA
├── 阅读伴侣主界面
├── 地图
├── 已读记忆
└── 剧透确认与安全展示

平台入口
├── Windows：Tauri 托盘、快捷键和区域截图
├── iOS：Swift Share Extension
├── 华为 Android：Android Share Target
└── 纯 HarmonyOS：ArkTS 分享入口
```

首个版本可以只实现 PWA 中的粘贴和截图上传，以验证按书建库、地名映射和剧透门禁；平台原生入口不应阻塞核心体验验证。

## 首本书验收范围

《飘》适合作为首个资料包。首版至少验收：

- 能区分亚特兰大等真实地点与塔拉庄园等虚构地点。
- 能展示主要地点的方向、距离和层级关系。
- 能根据指定译本识别常见人名、地名及别名。
- 当前进度之前的地点和人物事实可以正确过滤。
- 地图安全字段无需警告即可展示。
- 地点意义、人物关系和后续事件在展示前触发强提醒。
- 高风险问题必须经过二次确认。
- 生成后扫描能够拦截意外出现的未来剧情。
- 没有运行时大模型时，已发布地图和资料查询仍可工作。

## 建设顺序

1. 使用指定译本的最小章节证据审核《飘》staging 中的实体与事实候选，并显式发布首批章节资料。
2. 扩充无剧情地点覆盖，并审核模糊区域、原型地点和历史地图图层。
3. 用真实阅读流程校准截图 OCR、模型名称候选的误识别率和确认体验。
4. 在双阶段门禁与生成后扫描可验证前，不开放模型自由问答、关系解释或事实生成。
5. Windows PWA 流程稳定后，再评估全局快捷键原生壳、iOS 和华为原生分享入口。

## 待确认的产品选择

- 华为平板型号及 HarmonyOS 版本。

- 建库时允许使用的原文或参考资料来源。
- 当前 BYOK 浏览器直连是否长期保留，或在自由问答范围扩大前改用轻量后端或本地模型。
