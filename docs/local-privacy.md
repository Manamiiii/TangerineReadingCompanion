# 本机私有信息与公开仓库

GitHub 中只提交通用代码、文档、合成测试数据、项目图标和已审核的正式资料。个人机器信息、阅读数据与凭据保留在使用者自己的环境中，不作为默认配置发布。

| 信息 | 当前存放方式 |
|---|---|
| 安装目录、Node 和工具链位置 | 启动时通过脚本所在目录、系统环境变量或系统查询获得；不写入源码 |
| 模型接口、模型名、地图供应商等个人设置 | 当前浏览器、当前网站的 `localStorage`；不进入阅读备份 |
| 模型与地图 API Key | 当前会话的 `sessionStorage`；不进入源码、数据库、日志或导出 |
| 个人书籍、进度、已遇到名称和备注 | 当前浏览器的 IndexedDB；只在用户主动操作时导出 |
| 原文、截图、OCR 原文、临时模型结果与剧透授权 | 内存中的临时状态，遵循切书、清空、刷新等失效规则 |
| 启动日志、检测报告和测试结果 | Git 忽略的 `artifacts/`；可能包含本机信息，分享前检查 |
| Windows 桌面快捷方式 | 本机桌面；`.lnk` 不提交，通用 VBS 和图标可提交 |
| 维护者额外保存的本机配置文件 | 仓库外，或 Git 忽略的根目录 `.private/`；应用不会自动读取该目录 |

当前 Web/PWA 版本无需建立包含本机绝对路径的配置文件。`.private/` 是本机文件的保留位置，不是新增的设置接口，也不是加密存储。今后的原生安装版应通过系统 API 确定用户配置目录，不能把开发者机器目录作为默认值。

## 提交与构建前检查

运行 `npm run check:privacy`。检查覆盖 Git 已跟踪文件、未忽略的新文件以及整个 `public/`；下载 ZIP、没有 Git 元数据时使用目录扫描。它会阻止常见的本机绝对路径、已知密钥格式、内网服务 URL、私有配置文件和阅读导出包，输出文件位置与规则名，不打印命中的内容。

`npm run build` 会先运行该检查，CI 也单独执行。规则是启发式检查，不能识别所有密码、任意私人文字、图片中的信息或未知密钥格式；截图和新增资料仍需人工核对。提交前检查暂存区，不能依赖推送后的 CI 撤回已经公开的内容。

- `.gitignore` 已排除 `.env`、本机配置、常见凭据文件、日志、备份文件名和快捷方式。**已被 Git 跟踪的文件不会因为新增忽略规则而自动停止跟踪。**
- **不要把私有文件放在 `public/` 中**，即使它被 Git 忽略：Vite 会把该目录复制到构建产物。本项目的构建前检查专门覆盖这类文件。
- 不要通过 `VITE_*` 环境变量配置私钥；被前端引用的构建变量会出现在浏览器代码中。模型 Key 通过应用设置填写。
- 备份和反馈包含个人书目、备注或位置，不是可公开上传的诊断文件。改名不能使它们匿名，也不要将它们作为测试夹具。
- `.env.example` 只能提供占位值；示例、测试与文档使用虚构数据或公开标准地址，不复制真实凭据、内网地址和个人路径。

## 如果发现已经上传的私有信息

先停止继续传播相关文件。真实密钥须先撤销或轮换；当前版本删掉文件不代表历史、分支、Release、Actions 附件或其他人的副本已经消失。历史清理需要另行评估并取得授权，不能直接强推或改写 `main`。

Git 提交也包含作者元数据。维护者应使用 GitHub 提供的 noreply 邮箱；公开仓库账号与第三方许可中的作者署名是公开来源信息，不应当作本机配置删掉。
